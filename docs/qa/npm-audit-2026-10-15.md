# npm audit — 15 Oct 2026 (E10)

## Before E10 (Next.js 14.2.35, React 18)

13 findings: 1 critical, 9 high, 3 moderate. Almost all came from `next` itself: Next.js 14 no longer receives security fixes, and 23 advisories (including two critical remote-code-execution issues in the image optimiser and on Windows servers) are fixed only in Next.js 15.5.24 or later.

## After E10 (Next.js 15.5.28, React 19)

The upgrade removed every advisory against Next.js itself, including both critical ones. Next.js's own copy of PostCSS (8.4.31) was then pinned to the patched 8.5 line with an `overrides` entry in `package.json`.

What remains is build-time tooling only. None of it runs on the live site or ever sees visitor input:

| Package | Severity | Where it comes from | Why it does not affect visitors | Fix |
|---|---|---|---|---|
| `braces`, `micromatch`, `fast-glob`, `chokidar` | high | Tailwind CSS 3 (watches and finds our source files while building) | Runs only during `next build` on our own files | Tailwind CSS 4 (major rewrite of the styling setup) |
| `postcss-nested`, `postcss-selector-parser` | moderate | Tailwind CSS 3 and `@tailwindcss/typography` | Processes our own stylesheet at build time | Tailwind CSS 4 |
| `glob` (CLI command injection) | high | `eslint-config-next` → `@next/eslint-plugin-next` | Only the `glob` command-line tool is affected; ESLint uses it as a library, and only on developers' machines | Next.js 16's ESLint config |

Decision: these stay until a later, separate upgrade (Tailwind CSS 4, Next.js 16). Both are major upgrades outside this brief, which authorises Next.js 15 only. Recorded in docs/LAUNCH_REPORT.md (E10).

## Re-run after Section 26 (S12, 15 Oct 2026)

Every finding is in the same build-time tooling listed above (Tailwind CSS 3 and its file watcher/glob libraries, `@tailwindcss/typography`, `eslint-config-next`); none is in a package the live site runs. Decision unchanged.
